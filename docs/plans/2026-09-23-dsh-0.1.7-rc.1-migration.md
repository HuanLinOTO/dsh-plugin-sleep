## 行动

1. `package.json` peerDeps（`@deepseek-ai/dsh-tools`、`@deepseek-ai/dsh-llm`）在本任务开始前已由主控提升为 `^0.1.7-rc.1`；本任务确认之，未改 `version`。
2. **源码改动（唯一实质改动）**：用 registry `@deepseek-ai/dsh-tools@0.1.7-rc.1` 做静态校验时暴露一个真实的类型面回归，根因如下：
   - rc.1 的 `dsh-tools` 依赖 `@deepseek-ai/schemastery ~3.18.4`；该 scoped schemastery 的全局 `Schemastery` 命名空间新增 `Volatile`，与插件自带的 npm 未 scoped `schemastery@3.18.0`（最后一版，无 `Volatile`）在同一 TS program 中**声明合并**；
   - 合并使 `z.object({...}).default(...)` 的输出类型变成 `number | Volatile<...>`，`export const Config: z<Config>` 的显式注解不再可赋值（TS2322，`src/index.ts(30,14)`）。
   - 处理：`src/index.ts` 保留注解，值上加 `as unknown as z<Config>` 断言（纯类型断言，运行时构造 schema 仍走未 scoped 的 schemastery，行为不变）。
   - `src/types.d.ts` 头部注释更新为「0.1.7-rc.1 校对结论」并记录上述 schemastery 命名空间漂移；ambient 声明本身（`defineTool`/`DefineToolOptions`/`ToolRunContext`/`ContentBlock`）对插件所用成员无签名漂移，无需改签名。
3. 重建 `lib/`（预构建策略，`lib/` 入库）：`as` 断言被擦除，产物与迁移前逐字节一致（`git status` 未列 `lib/`）。
