# @huanlin/dsh-plugin-sleep · dsh 0.1.2-alpha.1 → alpha.2 迁移指南

> 生成日期：2026-08-30 · 依据：tag `dsh-v0.1.2-alpha.1` (cd5ef81481) → `dsh-v0.1.2-alpha.2` (0a53fb55be) 的只读 git 对象分析 + 插件源码逐文件核验。
> 插件路径：`D:/Projects/deepseek-harness/dsh-sleep`；dsh 只读源码树：`D:/Projects/deepseek-harness/dsh`（下文 git 命令均为只读）。

## 结论

**✅ 直接可升 —— 无需任何代码改动。**

本插件是 **host-only 单工具插件**（`inject = ['tools']` + 一个 `sleep` 工具），唯一依赖的 dsh 公开面是 `@deepseek-ai/dsh-tools` 的 `defineTool` / `ToolRunContext`、`@deepseek-ai/dsh-llm` 的 `ContentBlock`、cordis 的 `ctx.tools.register`。逐一核验 alpha2 源码：这三处公开 API **签名与行为全部未变**；alpha2 的破坏性变更（client 注入 hook 改名、connection 重构、folds→projections、gateway 失败词汇收敛）全部落在本插件不触碰的 client / api 内部层。vendor 升级（cordis 4.0.1→4.0.2、schemastery 3.18.1→3.18.2）均为 patch 级，peer semver 范围天然满足。

## 迁移步骤

**结论：零源码改动。`package.json` / `cordis.patch.yml` / `src/` / `tests/` 全部保持原样。**

1. **升级 dsh 本体**（人类操作，走「更新 DSH 源码 checkout」SOP）：`git -C ~/.dsh/source/current pull --ff-only` → `pnpm install --prefer-offline` → **全量 `pnpm run build`**（alpha2 新增 workspace 包，跳过 install/build 会报 `Cannot find package '@deepseek-ai/dsh-<new>'` 或 loader 错）。同时同步 dev clone（`D:/Projects/deepseek-harness/dsh` 保持 pristine）。
2. **插件源码**：无需改动。无需更新 peerDependencies（见上表）、无需改 `cordis.patch.yml`（insert 行 id/name/config 与 alpha2 loader 兼容）、无需改 `types.d.ts`。
   - 可选（纯文档）：`src/types.d.ts:7-8` 注释提到「DSH v0.1.2-alpha.1 checkout」，升级后可顺手把措辞改为「DSH v0.1.2-alpha.2 checkout」。不影响任何行为，不强制。
3. **重建 lib/**（可选但推荐，刷新产物）：
   ```powershell
   Push-Location D:\Projects\deepseek-harness\dsh-sleep
   pnpm run build    # tsc -p tsconfig.json && tsdown -c tsdown.config.ts → lib/
   Pop-Location
   ```
   说明：`lib/` 产物将 `@deepseek-ai/*` 全部 external，与 dsh 版本解耦，严格说不重建也能在 alpha.2 上运行；重建仅保证 `lib/index.d.ts` 与最新 tsc 输出一致。**profile 是 link: 引用，重建 lib/ 后 `~/.dsh/profiles/web/node_modules/@huanlin/dsh-plugin-sleep/lib/` 即时可见，无需 `dsh plugin add` 重装**（`dsh plugin update` 对 link: 依赖无效，勿执行）。
4. **profile 端验证**：确认上述 node_modules 路径下 `lib/index.js` 与 `cordis.patch.yml` 可见（link: 直连，无需重装动作）。
5. **重启与硬刷新**：由人类重启 `dsh web` 进程，浏览器 `Ctrl+Shift+R` 硬刷新后进行下节验证。
6. **对外发布**（如需随升级发新版）：走 huanlinoto 发布 SOP——`pnpm run build` → `git add lib/ && git commit && git push origin master`（link: 引用重建即生效；`github:` 消费者随后 `dsh plugin update`）；npm 侧 `npm pack --dry-run` 核对 files 清单（`lib/` + `cordis.patch.yml`）后 `pnpm publish`。本插件版本号无需因宿主升级而 bump（无 API 变化），如 bump 则 GitHub 仓库与 npm 保持一致。

## 升级后验证清单

> 前置：dsh web 已升级到 alpha.2 并重启，浏览器已 `Ctrl+Shift+R` 硬刷新。以下均在 web 会话内操作。

1. **加载无报错**：WebUI 启动不弹 `Failed to load plugins` / `missed the module table`；设置 → 插件清单页能看到 `@huanlin/dsh-plugin-sleep`（alpha2 的 ui-settings-plugin-inventory 有大改，但 host-only 插件的清单条目仍由通用清单机制提供——若清单缺失，属「待人工确认」项，先看 dsh web 控制台报错）。
2. **配置可见**：插件设置页显示 `maxDurationMs=60000`、`defaultDurationMs=0`（Schemastery schema 渲染走通用通道，alpha2 未改该通道）。
3. **工具注册成功**：新开会话，让模型调用 `sleep`：
   - 正常路径：`duration_ms: 2000` → 返回 `requested_ms: 2000, actual_ms ≈ 2000, cancelled: false, clamped: false`，渲染文本 `Slept ~2000ms`。
   - Clamp 路径：`duration_ms: 999999` → `clamped: true`，实际等待 ≈60s（或改小 `maxDurationMs` 后再测，避免久等）。
   - 零值路径：`duration_ms: 0` → 立即返回 `actual_ms: 0`。
4. **取消语义**：`duration_ms: 30000` 发起后，在 UI 打断该轮（停止生成）→ 工具结果应显示 `cancelled: true`（不抛错、会话不报 tool failure）。
5. **配置热重载**：在 GUI 设置页把 `maxDurationMs` 改为 `2000`，再请求 `duration_ms: 5000` → 返回 `clamped: true, actual_ms ≤ 2000`（cordis dispose/re-apply 自动重注册）。
6. **回归项**：其他工具（run_code 等）不受本插件影响，抽查一次正常调用即可；确认会话内无 `tools/change` 相关异常日志。
